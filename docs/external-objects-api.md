# Получение списков объектов из внешней системы

API позволяет заранее загрузить учеников в LMS, распределить их по группам и
сопоставить с аккаунтами после первого входа. Объект ученика должен существовать
в CRM, но регистрация ученика и его вход во внешнюю систему не требуются.

## Настройка доступа

В CRM откройте **Внешний вход** → нужный OIDC-клиент. Клиент должен быть активным
и конфиденциальным. В разделе **Доступ и данные → Списки объектов через внешнее
API** выберите нужные типы, например **Ученики**, и сохраните настройки.

По умолчанию доступ закрыт, в том числе для существующих клиентов. При настройке
клиента через административное API список передаётся в `allowed_object_types`,
например `["students"]`.
Роли и OIDC scopes сами по себе не предоставляют доступ к спискам. Для получения
фотографий дополнительно разрешите клиенту scope **`avatar`**. Разрешение отправлять
уведомления задаётся отдельно.

Используйте HTTP Basic с теми же `client_id` и `client_secret`, что и для OIDC.
Вызывать API следует с backend по HTTPS; храните secret в серверных секретах.
Пользовательский access token и предварительное получение токена не нужны.

## Запрос

```http
GET /api/external/objects/students?limit=100 HTTP/1.1
Host: lk.silaeder.ru
Authorization: Basic BASE64_CLIENT_ID_COLON_CLIENT_SECRET
```

Код типа в пути может быть любым существующим типом, явно разрешённым клиенту.

| Параметр | Значение |
| --- | --- |
| `limit` | Размер страницы, от 1 до 200, по умолчанию 100 |
| `after_id` | Выдать объекты с ID больше указанного; для первой страницы не нужен |
| `q` | Поиск подстроки в имени без учёта регистра, до 200 символов |

Пример:

```bash
curl --get --user "$CRM_CLIENT_ID:$CRM_CLIENT_SECRET" \
  --data-urlencode 'q=Иван' \
  --data-urlencode 'limit=100' \
  "$CRM_BASE_URL/api/external/objects/students"
```

## Ответ

```json
{
  "items": [
    {
      "sub": "0aa1f478-341a-47ad-884d-a48873baf182",
      "object_id": 42,
      "object_type": "students",
      "name": "Иван Иванов",
      "grade": 7,
      "picture": "https://lk.silaeder.ru/api/external/objects/students/0aa1f478-341a-47ad-884d-a48873baf182/avatar"
    }
  ],
  "next_after_id": null
}
```

`sub` — стабильный идентификатор объекта, совпадающий с `sub` при последующем
OIDC-входе ученика, если его аккаунт привязан к этому же объекту через инвайт.
Сохраняйте пару `(issuer, sub)` и используйте её для связи с локальным профилем
и членством в группах. `object_id` — локальный числовой ID для пагинации;
не используйте его или имя как ключ внешней личности.

`grade` нормализован так же, как в OIDC: целое число от 1 до 11 для ученика,
`null` для других типов или некорректного/незаполненного значения.
`picture` — защищённый URL аватарки; `null`, если клиенту не разрешён scope `avatar`
или доступной фотографии нет. Регистрация и вход ученика для получения фото не нужны.
Ответ содержит только перечисленные поля: произвольные атрибуты, контакты,
даты рождения, инвайты и данные аккаунтов не выдаются. Скрытые и удалённые
объекты исключены; скрытый тип объектов недоступен.

Объекты отсортированы по возрастанию ID. Если `next_after_id` не `null`, повторите
тот же запрос с `after_id`, равным этому значению, сохранив `q` и `limit`.
Когда `next_after_id` равен `null`, список закончился. Пустая выборка —
`{"items": [], "next_after_id": null}`. Пагинация не создаёт снимок данных:
параллельные изменения карточек могут влиять на следующие страницы.

## Получение аватарки до входа

Скачивайте URL из `picture` с той же HTTP Basic-аутентификацией:

```bash
curl --user "$CRM_CLIENT_ID:$CRM_CLIENT_SECRET" \
  --output avatar.png \
  "$CRM_BASE_URL/api/external/objects/students/0aa1f478-341a-47ad-884d-a48873baf182/avatar"
```

Endpoint `GET /api/external/objects/{type_code}/{sub}/avatar` возвращает сам файл.
Он требует одновременно доступ к типу объекта и разрешённый scope `avatar`.
Открытие ссылки в браузере без этих реквизитов не даст доступа: внешний сервис
должен скачать фото на backend, а затем показывать его в своей системе.
Secret нельзя включать в URL или передавать в браузер.

Выдаётся только фото из файлового атрибута `photo`, который не отмечен как
скрытый, секретный или приватный. Для атрибута с историей выбирается последний
доступный файл, как при OIDC-входе. Скрытые и удалённые объекты, скрытые типы,
отсутствующие и недоступные фото возвращают `404`. Другие файлы карточки через
этот endpoint недоступны. Ссылка использует стабильный `sub` и сохраняется после
регистрации; при замене фото тот же URL возвращает актуальный файл.

Права проверяются при каждом скачивании. Ответы содержат `Cache-Control: no-store`
и `Vary: Authorization`, поэтому отзыв доступа не обходится кешированием браузера.

## Ошибки

| HTTP-код | Причина |
| --- | --- |
| `401` | Basic-аутентификация отсутствует, secret неверный, клиент выключен или публичный |
| `403` | Тип не входит в `allowed_object_types` клиента; для скачивания фото также требуется scope `avatar` |
| `404` | Разрешённый тип больше не существует или скрыт; объект или его фото недоступны |
| `422` | Некорректный параметр поиска или пагинации |
| `429` | Превышен лимит 600 запросов в минуту с одного IP |

Ответы имеют `Cache-Control: no-store`. Отзыв разрешения, выключение клиента
и ротация secret действуют со следующего запроса.

Уведомления по полученному `sub` можно отправлять только после появления
привязанного аккаунта и при наличии отдельного разрешения; см.
[API уведомлений](external-notifications-api.md).
